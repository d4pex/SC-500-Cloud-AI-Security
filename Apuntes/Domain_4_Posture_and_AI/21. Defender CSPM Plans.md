Microsoft Defender for Cloud (MDC) no es una sola herramienta, es la suma de dos cosas:
* CSPM (Cloud Security Posture Management): El inspector de tu casa que revisa si dejaste la puerta abierta (Configuraciones y Políticas).
* Workload Protection Plans: Las alarmas y cámaras de seguridad (Defender for Servers, Defender for Storage, etc.) que avisan si alguien está forzando esa puerta.

1.Foundational CSPM (Gratis) vs. Defender CSPM (De pago)
El examen preguntará constantemente qué funciones exigen licencia de pago.
* Foundational CSPM (Gratuito): Viene activado por defecto. Incluye el Secure Score (Puntuación de seguridad), inventario básico de recursos, y cumplimiento normativo basado exclusivamente en el Microsoft Cloud Security Benchmark (MCSB).
* Defender CSPM (De pago): Se cobra por recurso/hora. Es vital para organizaciones maduras porque desbloquea:
	* Attack Path Analysis (Análisis de rutas de ataque): Dibuja un mapa visual de cómo un hacker podría encadenar varias vulnerabilidades pequeñas para llegar a tus joyas de la corona.
	* Cloud Security Graph: Para hacer consultas complejas (ej. "Encuentra todas las VMs públicas que pueden llegar a mi BD de facturación").
	* Agentless scanning (Escaneo sin agentes) para VMs y secretos.
	* Data-aware security (Sabe si una BD tiene datos sensibles de Purview).
	* Governance rules (Reglas de gobernanza para forzar a que los equipos arreglen sus problemas).
	* Otros estándares regulatorios (PCI-DSS, ISO, HIPAA, etc.).

2.Attack Path Analysis (El valor real de Defender CSPM)
* En lugar de darte una lista plana de 500 errores (ej. "Cierra este puerto", "Actualiza este software"), Attack Path Analysis te dice: "Si no arreglas el servidor X y a la vez la Identidad Y, un atacante usará X para robar Y y borrar tu base de datos".
* El Choke Point (Punto de estrangulamiento): Es el nodo en el grafo que cruza múltiples rutas de ataque. Tip de examen: Si te preguntan qué arreglar primero cuando hay 10 rutas de ataque, la respuesta es "Arreglar el choke point" (el recurso que colapsará las 10 rutas a la vez con un solo cambio).

3.El Secure Score (Puntuación de Seguridad)
* Es un porcentaje (0-100%). No te da puntos parciales. Para conseguir los puntos de la categoría "Habilitar MFA", todos los recursos aplicables deben cumplirlo. Si te falta uno, tienes 0 puntos en esa categoría.
* Uso: Sirve para informes a directivos, no para el trabajo diario del SOC. Para el triaje diario, filtra por severidad (High/Critical).

4.Reglas de Gobernanza (Governance Rules)
* El problema: Tienes mil alertas de "Falta un parche", y nadie de tu equipo de desarrollo las arregla.
* La solución: Las Reglas de Gobernanza (exclusivas del plan de pago CSPM). Te permiten asignar automáticamente un Propietario (Owner) y un SLA (Tiempo límite de resolución) a las alertas basadas en etiquetas (ej. Si el recurso tiene el Tag Departamento: Finanzas, asignar a "AdminFinanzas@empresa.com" con un SLA de 14 días para alertas críticas).

5.El Despliegue Perfecto (El patrón de arquitectura)
Si un caso de estudio te pregunta cómo configurar Defender for Cloud a nivel empresarial, los pasos (y sus alcances) son:
* Habilitar Defender CSPM a nivel de Management Group (para que todas las suscripciones actuales y futuras lo hereden).
* Habilitar los Workload Protection Plans (Defender for Storage, SQL, Servers, etc.) a nivel de Suscripción.
* Asignar las Reglas de Gobernanza (Governance rules) con SLA.
* Exportar todo al SIEM (Microsoft Sentinel) mediante el conector nativo.
