El examen SC-500 te presentará menús desplegables (Drop-downs) o preguntas de opción múltiple con comandos. Tu objetivo es entender qué hace el comando leyendo sus parámetros, no memorizar la sintaxis exacta.

1.La Regla de Oro: Reconocer, no recordar (Recognition beats recall)
* Azure CLI: Usa el formato az [recurso] [acción]. Ej. az keyvault create.
* PowerShell: Usa el formato Verbo-Sustantivo. Ej. New-AzKeyVault.
* No mezcles la sintaxis mentalmente. Si ves az, es CLI. Si ves un guion entre mayúsculas (Get-Az...), es PowerShell.

2.Inicio de Sesión y Contexto (Login & Context)
* CLI: az login y luego az account set --subscription [ID].
* PowerShell: Connect-AzAccount y luego Set-AzContext.
* El error clásico: Asumir que estás en la suscripción correcta. Siempre debes verificar el contexto antes de ejecutar un script destructivo o de seguridad.

3.Identidad y RBAC (Role-Based Access Control)
* Para asignar un rol (ej. Key Vault Secrets User):
	* CLI: az role assignment create --assignee [usuario] --role [rol] --scope [recurso]
	* PowerShell: New-AzRoleAssignment
* Nota: CLI usa az ad (basado en Microsoft Graph) para buscar usuarios, mientras que PowerShell usa comandos directos de AzureAD/MgGraph.

4.NSGs (Network Security Groups)
* CLI (De un solo disparo): Crea la regla y la aplica directamente. az network nsg rule create --priority 100 --destination-port-ranges 443 --access Allow
* PowerShell (3 pasos): Obtiene el NSG en memoria (Get), le añade la regla en memoria (Add), y lo guarda (Set).

5.La Trampa del Private Endpoint
Si ves un comando que crea un Private Endpoint (az network private-endpoint create), recuerda que el trabajo no está terminado.
* Pregunta de examen: "Has creado el endpoint pero sigue resolviendo a la IP pública, ¿qué falta?".
* Respuesta: Falta el comando para vincularlo a la Private DNS Zone. Sin la zona DNS, el endpoint no sirve de nada.

6.Azure Firewall
* Recuerda la jerarquía: Primero creas la Policy (Política), luego la Rule Collection (Colección de reglas) y finalmente adjuntas la política al Firewall.
* Si el comando incluye --sku Premium, es porque se necesitan funciones avanzadas como TLS Inspection o IDPS.

7.Endurecimiento de Storage Accounts (Storage Hardening)
Este es el comando más preguntado en el examen. Tienes que reconocer el comando que hace las 4 cosas del "Patrón Canónico":
* --allow-shared-key-access false (Fuerza Entra ID).
* --min-tls-version TLS1_2 (Seguridad en tránsito).
* --public-network-access Disabled (Bloquea internet).
* --default-action Deny (Reglas de red estrictas).
* Si ves un comando con esos 4 flags, esa es la respuesta correcta para endurecer el almacenamiento.

8.Key Vault
* Los comandos de creación seguros incluirán: --enable-rbac-authorization true (para usar Azure RBAC en lugar de Access Policies) y --enable-purge-protection true (para evitar el borrado malicioso).

9.Consultas y Filtrado (El flag --query)
* En Azure CLI, si ves el parámetro --query, está usando el lenguaje JMESPath para filtrar los resultados antes de mostrarlos en pantalla.
* Se usa para auditorías rápidas. Ej. "Muéstrame solo el nombre de las VMs que no tienen encriptación". Utiliza corchetes [] para filtrar y llaves {} para proyectar campos.
