La regla de oro de este capítulo: Nunca, bajo ninguna circunstancia, una máquina virtual debería tener el puerto 3389 (RDP) o 22 (SSH) abierto públicamente. La solución es la combinación de Bastion + JIT + Cifrado.

1.Azure Bastion (El Conserje del Hotel)
Bastion es un "Jump server" totalmente gestionado por Microsoft. Accedes a tus VMs directamente desde el navegador web en el portal de Azure, sin necesidad de VPN ni de IPs públicas en tus máquinas.
* Requisito técnico: Necesita su propia subred dedicada llamada exactamente AzureBastionSubnet (es sensible a mayúsculas y minúsculas) con al menos un tamaño de /26.
* Las 3 Versiones (Tiers) de Bastion:
	* Developer (Gratis): Para laboratorios de una sola VM. Sin opciones avanzadas.
	* Standard (El estándar): Múltiples sesiones concurrentes, copiar/pegar archivos y soporte para clientes nativos (usar tu propio cliente SSH/RDP local a través del túnel).
	* Premium (Para auditorías): ¡PREGUNTA DE EXAMEN! Si el escenario te pide "Session Recording" (Grabar las sesiones en vídeo) o que el propio host de Bastion no tenga IP pública (Private-only connectivity), la respuesta es el tier Premium.

2.JIT (Just-In-Time) VM Access
Bastion soluciona cómo te conectas, pero JIT soluciona cuándo se abre el puerto.
* Es una característica incluida en Defender for Servers Plan 2.
* ¿Cómo funciona? Por defecto, JIT mantiene los puertos de administración (RDP/SSH) bloqueados con una regla de "Deny" en el NSG. Cuando un administrador necesita entrar, solicita acceso. Si se aprueba, JIT escribe temporalmente una regla de "Allow" en el NSG por un tiempo máximo (ej. 3 horas). Cuando expira el tiempo, la regla se borra automáticamente.
* Se puede combinar perfectamente con aprobaciones manuales y con Políticas de Acceso Condicional (ej. requerir MFA antes de poder solicitar el acceso JIT).

3.Opciones de Cifrado de Discos
Hay cuatro sabores principales. Tienes que saber diferenciar entre el modelo antiguo y el moderno:
* Server-Side Encryption (Plataforma): Es el cifrado por defecto. Protege el disco persistente, pero las claves las maneja Microsoft.
* Server-Side Encryption con CMK (Customer Managed Key): Cifra el disco persistente, pero las claves están en tu Key Vault.
* Azure Disk Encryption (ADE): El método antiguo/Legacy. Usaba BitLocker en Windows y DM-Crypt en Linux dentro del sistema operativo. Ya casi no se recomienda para nuevos despliegues.
* Encryption at Host (¡EL ESTÁNDAR MODERNO!): Cifra no solo el disco persistente, sino también el disco temporal y la caché del host. Todo el cifrado ocurre en el servidor físico de Azure antes de que los datos viajen por la red de almacenamiento. Es el modelo más completo y el que debes elegir.

4.Trusted Launch y Confidential VMs
Protegen contra ataques súper avanzados (como bootkits o rootkits).
* Trusted Launch: Es el nuevo estándar de seguridad al crear una VM. Incluye:
	* Secure Boot (Arranque Seguro): Bloquea cargadores de arranque no firmados o maliciosos.
	* Virtual TPM (vTPM): Un chip de seguridad virtual que almacena las claves de cifrado (como las de BitLocker) de forma aislada.
* Confidential VMs: Van un paso más allá. Cifran literalmente la memoria RAM de la máquina virtual mientras está en uso. Si el escenario de examen dice "Requerimos que ni siquiera los administradores del centro de datos de Microsoft puedan ver los datos procesados en memoria", la respuesta es Confidential VMs.
