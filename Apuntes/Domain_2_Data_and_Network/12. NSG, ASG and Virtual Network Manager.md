En Azure, el filtrado de red se basa en prioridades, reglas implícitas y control centralizado. Es fundamental entender cómo se aplican las reglas para no bloquearte a ti mismo.

1.NSG (Network Security Groups): Las Reglas Base
* ¿Qué son? Una lista ordenada de reglas de Permitir (Allow) o Denegar (Deny). Se pueden aplicar a una Subred entera o a una Tarjeta de Red (NIC) individual.
* Prioridad (Priority): Es un número del 100 al 4096. El número más bajo gana. Azure lee de arriba a abajo; en cuanto encuentra la primera regla que coincida con el tráfico, ejecuta la acción y deja de leer el resto.
* Stateful (Con estado): Los NSG "tienen memoria". Si creas una regla de entrada (Inbound) permitiendo el puerto 443, la respuesta de salida (Outbound) pasa automáticamente. Trampa de examen: Nunca escribas reglas duplicadas de entrada/salida para el mismo tráfico.

La Evaluación Doble:
* Si tienes un NSG en la Subred y otro NSG en la Tarjeta de Red (NIC) de la Máquina Virtual:
* Ambos NSGs se evalúan.
* La regla más restrictiva gana. Si el NSG de la subred dice "Allow" pero el NSG de la tarjeta de red dice "Deny", el paquete es destruido.

2.Las 6 Reglas por Defecto (Default Rules)
No puedes borrarlas, pero puedes crear reglas con menor número para anularlas.
* La trampa del Outbound: La regla por defecto AllowInternetOutBound (Prioridad 65001) permite a cualquier máquina salir a Internet. Muchas personas asumen que Azure bloquea todo por defecto, pero no es así. Si quieres evitar que una base de datos salga a Internet, tienes que escribir una regla explícita de "Deny Internet".

3.ASG (Application Security Groups): Las Etiquetas
* En lugar de usar direcciones IP a mano (lo cual es inmanejable si tienes 50 servidores web), creas un ASG llamado "ServidoresWeb" y se lo asignas a las máquinas.
* Luego, en tu NSG, escribes la regla: "Permitir tráfico desde [ASG-ServidoresWeb] hacia [ASG-BasesDeDatos]".
* Si creas un nuevo servidor, solo le pones la etiqueta y la regla ya funciona. Escala perfectamente.

4.Service Tags (Etiquetas de Servicio de Microsoft)
* Microsoft posee miles de direcciones IP (para Azure SQL, Key Vault, Storage, etc.) que cambian constantemente.
* En lugar de escribir IPs, usas un Service Tag. Ej: "Permitir salida hacia AzureKeyVault". Azure se encarga de actualizar automáticamente las IPs que hay detrás de esa etiqueta.
* Tip de Examen: Siempre prefiere usar un Service Tag específico (ej. AzureKeyVault) antes que uno general (ej. Internet o AzureCloud).

5.Azure Virtual Network Manager (AVNM) y Security Admin Rules
* El problema: Si tienes 100 equipos de desarrollo, cada uno controlando su propio NSG, ¿cómo garantizas que nadie abra el puerto 22 (SSH) a todo Internet por error?
* La solución (AVNM): AVNM permite al equipo central de seguridad crear Security Admin Rules.
* La Regla de Oro: Las Security Admin Rules SIEMPRE SOBREESCRIBEN a los NSGs locales. Si una Admin Rule dice "Denegar Puerto 22", da igual que el NSG del desarrollador diga "Permitir", la conexión será bloqueada. Si una pregunta menciona "El equipo de plataforma fuerza una política y el desarrollador no puede arreglar su conexión modificando su NSG", la culpa la tiene una AVNM Admin Rule.
