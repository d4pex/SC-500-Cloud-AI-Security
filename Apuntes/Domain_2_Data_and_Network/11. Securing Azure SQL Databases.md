Asegurar una base de datos significa garantizar que nadie, a veces ni siquiera el propio administrador de la base de datos, pueda leer los datos sensibles que no le corresponden.

1.Los tres "sabores" de Azure SQL (Clave para escenarios de arquitectura)
* Azure SQL Database: (El apartamento de servicio). Totalmente administrado. Ideal para bases de datos individuales modernas hechas para la nube. No hay servidor visible ni agente SQL.
* Azure SQL Managed Instance: (El adosado). Es el punto intermedio. Totalmente administrado, pero con características legacy como SQL Agent, consultas cruzadas entre bases de datos y despliegue dentro de una VNet privada. Tip de Examen: Si la pregunta dice "Lift and Shift con mínimos cambios desde un servidor on-premise", la respuesta es SIEMPRE Managed Instance.
* SQL Server on Azure VM: (La casa independiente). Máquina virtual (IaaS). Tú gestionas el sistema operativo, los parches y el servidor SQL. Solo lo usas si necesitas control absoluto a nivel de sistema operativo.

2.Autenticación: Entra-only Authentication
* SQL Authentication (El problema): Usa usuarios y contraseñas locales guardados en la base de datos. Se filtran, acaban en repositorios de código y no soportan MFA.
* Entra Authentication (La solución): Inicios de sesión vinculados a identidades reales de Entra ID.
* El paso definitivo (Entra-only authentication): Existe un botón en el portal llamado "Entra-only authentication" que desactiva por completo el inicio de sesión local SQL. Precaución: Antes de encender esto, debes revisar los logs de sesión para asegurarte de que ninguna aplicación antigua se rompa al desconectarla.

3.Las 3 Capas de Cifrado (Encryption)
El examen preguntará contra qué amenaza te protege cada tipo de cifrado:
* Transparent Data Encryption (TDE): Protege "Data at Rest" (Datos en reposo). Cifra el disco. Si alguien roba físicamente el disco duro del centro de datos de Microsoft, no podrá leer nada. Viene activado por defecto.
* Always Encrypted (Siempre cifrado): Protege contra el administrador malicioso. Los datos se cifran en el cliente (la aplicación web) antes de enviarse a la base de datos, y se descifran en el cliente al recibirlos. La base de datos (y su administrador) solo ve texto cifrado.
* Secure Enclaves: Una mejora de Always Encrypted que permite a la base de datos hacer búsquedas de texto y comparaciones (ej. buscar un nombre) sobre datos cifrados sin descifrarlos del todo, utilizando un espacio de memoria aislado ("enclave").
* In-Transit Encryption: Cifrado en tránsito (TLS). Viene forzado por defecto.

4.Ocultamiento de Datos (Data Hiding)
Esto no cifra los datos en el disco, simplemente cambia lo que ve el usuario en la pantalla:
* Dynamic Data Masking (DDM): Enmascara el contenido de una columna. Si un usuario de soporte hace un "SELECT *", en lugar de ver la tarjeta de crédito real, verá XXXX-XXXX-XXXX-1234. No cambia los datos físicos, solo la visualización para usuarios sin privilegios.
* Row-Level Security (RLS): Oculta filas enteras. Si el representante de ventas de España entra, la base de datos filtra silenciosamente y solo le muestra las filas (clientes) de España. Ni siquiera sabe que existen las filas de Francia. Se implementa con funciones de predicado en la base de datos.

5.Microsoft Defender for SQL
Se compone de dos herramientas que trabajan juntas:
* Vulnerability Assessment (Evaluación de vulnerabilidades): Es un escáner semanal. Chequea si tienes contraseñas débiles, si los permisos son excesivos o si te faltan reglas de firewall. Te da una lista de tareas (postura de seguridad).
* Advanced Threat Protection (Protección avanzada contra amenazas): Es la alarma en tiempo real. Vigila anomalías como inyecciones SQL (SQLi), fuerza bruta de contraseñas, o accesos desde IPs y países inusuales, enviando alertas a Sentinel.
* Mejor práctica: Al igual que Defender for Storage, debes activar Defender for SQL a nivel de suscripción, no base de datos por base de datos, para que todo recurso nuevo nazca protegido.
