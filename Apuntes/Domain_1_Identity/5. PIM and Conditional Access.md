Este capítulo soluciona dos de los problemas más graves en la nube: administradores con demasiados privilegios permanentes y políticas de acceso mal configuradas que bloquean a la empresa entera.

1.Privileged Identity Management (PIM)
Tener cuentas con el rol de Administrador Global (Global Administrator) de forma permanente no significa tener administradores, significa tener "vías de ataque". PIM transforma los derechos permanentes en derechos limitados en el tiempo, auditables y sujetos a aprobación.
* Configuraciones Clave al activar un rol (Ej. Global Admin):
	* Duración máxima de activación: Por defecto son 8 horas, pero en entornos seguros se baja a 1 o 2 horas.
	* Requerir MFA: Siempre debe estar encendido para activar un rol.
	* Justificación y Tickets: Obliga al usuario a escribir por qué necesita el rol e introducir un número de ticket de soporte (oro puro para auditorías).
	* Aprobadores: El rol no se activa hasta que alguien de seguridad lo aprueba.
* Asignaciones: Eligible (Elegible) vs. Active (Activo)
	* Eligible: El usuario puede convertirse en administrador si lo pide, pero en su día a día no tiene permisos administrativos. Si le roban la sesión, el atacante no tiene permisos.
	* Active: El usuario ha activado el rol y, durante esa ventana de tiempo (ej. 1 hora), su token contiene los permisos de administrador.
*Nota para el examen: PIM funciona tanto para roles de Entra ID (identidades) como para roles RBAC de Azure (recursos), pero se configuran en sitios diferentes.

2.Conditional Access (Acceso Condicional)
Es el portero de la discoteca de tu Tenant. Se interpone en cada inicio de sesión y decide si el usuario entra, se le bloquea o se le pide más información (MFA).

Estructura de una Política de Acceso Condicional:
* Asignaciones (Quién y Qué):
	* Usuarios: A quién aplica. Regla de oro absoluta: SIEMPRE debes excluir tu cuenta de emergencia ("Break-glass account") de TODAS las políticas, o podrías quedarte fuera de tu propio tenant.
	* Target resources: A qué aplicaciones intentan acceder (Ej. Todo Microsoft 365, el portal de Azure, etc.).
* Condiciones (Cuándo): El contexto del inicio de sesión.
	* Riesgo del usuario o riesgo del inicio de sesión (viene de Entra ID Protection).
	* Ubicaciones (Países o rangos de IP).
	* Plataforma del dispositivo (iOS, Android, Windows).
* Controles (Qué pasa):
	* Block: Bloqueo directo.
	* Grant (Permitir): Pero requiriendo algo a cambio, como exigir MFA o exigir que el dispositivo esté marcado como Compliant (Cumplimiento a través de Intune).

Evaluación de las Políticas:
Las políticas de Acceso Condicional se evalúan en paralelo, no en orden. Si un inicio de sesión activa tres políticas distintas (dos de ellas permiten el acceso y una lo bloquea), el bloqueo siempre gana ("The most restrictive result always wins").

3.Testeo Seguro: What If y Report-Only Mode
Antes de activar una política para toda la empresa, debes usar las redes de seguridad:
* Report-only mode (Modo Solo Informe): La política se despliega pero no bloquea a nadie, simplemente registra en los logs ("sign-in logs") qué hubiera pasado si estuviera activa. Úsala durante al menos una semana antes de encender una política real.
* What If (Simulador): Una herramienta donde metes datos falsos (Ej. "Usuario X desde China en un iPhone") y Azure te dice exactamente qué políticas se le aplicarían y si entraría o no.

4.Authentication Context (Contexto de Autenticación)
Sirve para aplicar seguridad "dentro" de una aplicación. Por ejemplo, permitir que un usuario entre a SharePoint normalmente, pero si intenta descargar un documento confidencial, el Authentication Context salta y le pide reautenticarse con una llave de seguridad física.

5.El Kit de Supervivencia "Zero Trust" (Políticas por defecto)
Cualquier tenant serio debe tener este conjunto de políticas el primer día:
* Bloquear Autenticación Heredada (Legacy Authentication).
* MFA requerido para todos los usuarios.
* MFA resistente a Phishing para los administradores.
* Restricciones de ubicación (bloquear países donde no se hace negocio).
* Requerir dispositivos en cumplimiento (Compliant) para las apps sensibles.
